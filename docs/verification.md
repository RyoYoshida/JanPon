# 検証の実行方法と現在の範囲

この文書は、自動検証で確認できる範囲と未実施の確認をまとめたものです。画面の仕上がりや遊べることだけをもって、すべての実機・障害条件を確認済みとはしていません。

## 実行方法

Node.js 24.0.0以上を使い、リポジトリのルートで実行します。

```sh
node --version
npm ci
npm run check
```

用途に応じて、次のコマンドを個別に実行してください。

| コマンド | 内容 | 終了コード |
| --- | --- | --- |
| `npm run build` | TypeScriptの厳密ビルド、登録・拡張の自動発見 | 正常0、失敗1 |
| `npm run build:game` | ビルド後、単一HTMLとマニフェストを生成 | 正常0、失敗時は非0 |
| `npm run check` | ビルド、HTML生成、アーキテクチャ・仕様・自動テスト | `PASS` は0、失敗1 |
| `npm run check:checkpoint` | 通常検証と9種類の故障注入 | `PASS` は0、失敗1 |
| `npm run check:faults` | 一時コピーで故障を検出し、元のソース・期待値が不変で正常検証に戻ることを確認 | 正常0、失敗1 |
| `npm run check:complete` | 通常検証を行い、未完成の検証状態を出力 | 検証が通っても `NOT_READY` の2、失敗1 |
| `node tools/check-stage8-add-only.mjs` | 非公開の旧基準との差分を調べていた履歴専用検査 | 公開版では `NOT_AVAILABLE` の2 |

`check:complete` の `NOT_READY` は現在のコードに固定されています。実行回数や経過時間で解除されず、このコマンドは100,000ラウンド検証や実ブラウザ試験を追加実行しません。終了コード2を成功へ読み替えないでください。

履歴専用の `check-stage8-add-only.mjs` は、公開版から比較元の非公開履歴を除いたため実行できません。代替の合格結果を作らず、`NOT_AVAILABLE` として扱います。通常の `check` / `check:checkpoint` とは別の検査です。

## 出力と副作用

- `build` は `dist/` を削除して作り直します。HTMLが必要な場合は、その後に `build:game` または `check` を実行します
- `build:game` は `dist/JanPon.html` と `dist/JanPon.manifest.json` を生成します。マニフェストにはソース内容とHTMLのSHA-256が含まれます
- 通常・節目・完成モードの実行結果は、それぞれ `.verification/everyday.json`・`checkpoint.json`・`complete.json` に保存されます。故障注入の成功結果は `.verification/faults.json` に保存されます
- 通常検証の時間上限は180秒、節目検証は3600秒です。これらは検証コマンドの制限であり、端末での描画性能の保証値ではありません
- 故障注入はOSの一時ディレクトリに作ったプロジェクトコピーを変更し、終了時に削除します。元の `src/` と仕様の期待値は変更しません
- レポートや生成物はGit管理対象外です。古いレポートを現行コードの結果として扱わず、実行日時・対象版・終了コードを合わせて確認してください

## 確認できていること

公開準備時に、Node.js 24.19.0で通常検証と節目検証を実行し、次を確認しています。

- 9種類の故障注入をすべて検出し、正常状態での再検証も成功
- **173テスト成功**、失敗・キャンセル・スキップ・TODOはいずれも0
- **10,000決着ラウンド**を進行し、記録した入力の決定列から**10,000ラウンドを再生**して状態を照合
- 上記のラウンド試験で、例外・不変条件違反・再生状態の不一致は0
- 配当の全100スロット、最後の1枚、無料のあいこ、リスタート、重複入力・精算の抑止などのテスト
- 保存失敗・確定が不明な書き込み・復元・別タブ所有権などを、注入した保存・所有権の実装でテスト
- キーボード、音声拒否、動き控えめ、表示の状態遷移などを、テスト用のDOM・音声・時計でテスト
- 単一HTMLのハッシュ整合性、外部スクリプト・外部スタイルシートがないこと、JavaScriptの構文を検査

ラウンド試験は本体と同じ `Game` / `progress` を通ります。ただし、保存はメモリ上のテスト実装、表示待ちは短絡した実装です。実ブラウザのIndexedDB、Web Locks、描画、音声で10,000回操作した記録ではありません。

仕様の期待値照合と構文・依存グラフの検査も、あらゆる実装や障害に対する安全性を証明するものではありません。

## 未実施・未確認

- **100,000決着ラウンドと再生：`NOT_RUN`**。10,000ラウンドの結果から外挿しません
- **正確なOS・ブラウザ版を記録した実機検証：`NOT_RUN`**。対象候補はPCのChrome、iPhoneのSafari、AndroidのChromeです。対応保証済みの一覧ではありません
- 実機での保存中断・復帰、複数タブ、背景からの復帰、音声拒否、操作・表示・動き控えめを組み合わせた網羅的な確認は未完了です
- `check:complete` の終了0による完了判定は未実装です。`check` や `check:checkpoint` の `PASS` を全項目の検証完了とは扱いません

## 実機確認を行う場合の記録

[READMEの起動手順](../README.md#ローカルで起動する)で配信したHTMLを使い、端末名、OSの正確な版、ブラウザの正確な版、実行日、ソースの版、HTMLのSHA-256、実施した操作と結果を記録してください。

少なくとも、通常の投入と全勝敗、連続あいこ、残高0からの再開、各進行状態での再読み込み、同一オリジンの別タブ、背景復帰、キーボード・タッチ、ミュート・動き控えめを確認します。通常の再読み込みだけで、保存中断や破損からの復帰を検証したとは扱いません。破損・中断の試験には通常プレイと分離したブラウザプロファイルを使ってください。

Web Locksと保存はブラウザが提供する機能です。APIの性質は [Web Locks仕様](https://w3c.github.io/web-locks/) と [IndexedDB仕様](https://w3c.github.io/IndexedDB/) を参照できます。API仕様の存在や対応情報だけでは、JanPon自身の実機検証の代わりになりません。
