# JanPon

じゃんけんとルーレットを組み合わせた、ブラウザで遊ぶ1人用メダルゲームです。TypeScript製のフロントエンドで動作し、進行状況はブラウザ内のIndexedDBに保存します。アカウントやバックエンドは不要です。

メダルはゲーム内だけの数値です。実際のお金の投入、課金、換金、景品交換はありません。画面のSVGと効果音は独自に制作・生成しています。

## 遊び方

1. 最初の持ちメダルは10枚。コインと残高の周辺を押すと、1枚を使って開始します。
2. グー・チョキ・パーから手を選びます。あいこは追加投入なしでもう一度。
3. 勝つとルーレットが自動停止し、1・2・4・7・20枚のいずれかを加算します。停止タイミングの操作は不要です。
4. 負けると配当なしで次へ進みます。残高が0枚になると、リスタートで10枚から遊び直せます。

- マウス・タッチで操作できます
- キーボードは `Tab` で移動し、フォーカスしたボタンを `Enter` / `Space` で実行します
- 手を選べる間は `R`＝グー、`S`＝チョキ、`P`＝パー。次の操作前にキーを離してください
- 筐体下部のボタンでミュートと「動き控えめ」を切り替えられます。動き控えめはOSの設定にも対応します
- 音声はWeb Audioによる合成音です。ブラウザが音声を許可しない場合もゲームは進行します

## ローカルで起動する

必要なもの:

- Node.js **24.0.0以上** と npm
- JavaScript、IndexedDB、Web Locks APIが利用できるブラウザ
- 下記の配信例を使う場合はPython 3

リポジトリのルートで実行します。TypeScriptは開発依存なので、省略せずインストールしてください。

```sh
npm ci
npm run build:game
python3 -m http.server 8000 --bind 127.0.0.1 --directory dist
```

ブラウザで [JanPonを開く](http://127.0.0.1:8000/JanPon.html)。サーバーは `Ctrl+C` で終了します。

`dist/JanPon.html` はCSS・JavaScript・SVGを含む単一HTMLです。実行時にCDNや外部の画像・音声ファイルを必要としません。ただし、ファイルを直接開く `file://` 方式は動作確認の対象としていません。上記のローカルHTTPサーバー、またはHTTPSで配信してください。Web Locksには[安全なコンテキスト](https://w3c.github.io/webappsec-secure-contexts/#is-origin-trustworthy)が必要です。

## GitHub Pagesで公開する

初回のみ、管理者がリポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定してください。

その後は `main` への更新で `Publish JanPon to GitHub Pages` が自動実行されます。Actions画面から手動実行もできます。Node.js 24で依存物をロックファイルどおりに導入し、ビルド・自動検証後、ゲーム本体だけを `index.html` として配信します。生成コードや検証用ファイルは配信しません。

公開URLは成功したActions実行の `github-pages` 環境に表示されます。初回設定前に実行が失敗した場合は、設定後にActions画面から再実行してください。サイトはインターネット上に公開されます。

## 保存とブラウザの制約

- 残高、進行中のラウンド、確定結果、精算状態をローカル保存します。クラウド同期・バックアップ・ファイル入出力はありません
- 同じブラウザの同じプロファイル・同じオリジンで再開してください。URLのホスト・ポート・HTTP/HTTPSが変わると保存先も変わります
- サイトデータの削除やプライベートブラウズなどで保存内容を失う場合があります。保存の永続性は保証しません
- 同じ保存先では1つのタブだけがプレイできます。「別のタブでプレイ中」の場合は、そのタブを閉じてから再試行してください
- IndexedDBまたはWeb Locksが利用できない場合、保存・復元が失敗した場合、保存内容が不正な場合は停止します。失敗した保存を成功扱いしたり、破損したデータを自動で消したりしません

必要なAPIが利用できることと、端末での動作確認が済んでいることは別です。正確なOS・ブラウザ版を記録した実機検証は未実施です。[検証状況](docs/verification.md)を参照してください。

## 開発用コマンド

```sh
npm run check
npm run check:checkpoint
npm run check:complete
```

- `npm run build`：厳密なTypeScriptビルド。単一HTMLは生成しません
- `npm run build:game`：ビルド後、`dist/JanPon.html` とマニフェストを生成します
- `npm run check`：ビルド、HTML生成、仕様・アーキテクチャ・自動テストを実行します
- `npm run check:checkpoint`：通常検証に加え、一時コピーへの9種類の故障注入を実行します
- `npm run check:complete`：現在の実装では検証が通っても **`NOT_READY`・終了コード2** です。完全検証済みを判定するコマンドとしては使えません

`build` は毎回 `dist/` を作り直します。HTMLを遊ぶ前には `build:game` または `check` を実行してください。生成物は `dist/`・`.generated/`、検証結果は `.verification/` に出力され、Git管理対象には含みません。

確認済みの自動テストは173件と、同じアプリケーション進行経路による10,000決着ラウンド・10,000ラウンド再生です。100,000ラウンド検証と実機検証は `NOT_RUN` です。範囲と終了コードの詳細は [docs/verification.md](docs/verification.md) に記載しています。

## 構成

- `src/core/`：状態、ルール、不変条件
- `src/application/`：ゲーム進行、入力と再生
- `src/adapters/`：画面、音声、入力、IndexedDB、Web Locks
- `game/`：HTMLとCSS
- `tests/`：自動テストと仕様の期待値
- `tools/`：ビルド、単一HTML生成、検証
- `mock/`：表示確認用モック。実際のゲーム本体は `src/` と `game/` です

公開用に履歴と文書を整理しています。ゲーム本体のコードは公開準備のためには変更していません。
